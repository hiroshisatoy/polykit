# PolyKit ポップアップと画面翻訳設定の設計

## 1. 文書の目的

本書は、PolyKit のツールバーポップアップと
「UI を日本語に翻訳」設定の最終仕様を定義する。

対象読者は、PolyKit の開発に初めて参加する開発者である。
本書だけで機能の目的、構成、データフロー、異常時の動作、
および検証方法を理解できることを目標とする。

## 2. 背景と目的

PolyKit は、`translate.wordpress.org` で日本語翻訳作業を支援する
ブラウザー拡張機能である。

利用頻度の高い操作をページ内の設定画面だけに置くと、設定変更のために
対象ページへ移動する必要がある。
ツールバーアイコンから開くポップアップに主要操作を配置し、次の操作を
どのページからでも実行できるようにする。

- GlotPress の画面を日本語化する機能の有効化と無効化
- PolyKit の全設定画面を開く操作

## 3. 設計原則

### 3.1 設定値の正本

`chrome.storage.local` を拡張機能全体で共有する設定値の正本とする。

ページ内で動作する既存の PolyKit スクリプトは `localStorage` を参照するため、
コンテンツスクリプトが共有設定をページ側へミラーする。
`localStorage` は互換用のキャッシュであり、共有設定より優先しない。

### 3.2 対象サイトの限定

ページへの直接操作は `https://translate.wordpress.org/` 以下に限定する。
それ以外のページでは PolyKit のコンテンツスクリプトへメッセージを送信しない。

### 3.3 安全な縮退

対象タブが存在しない場合やメッセージ送信に失敗した場合も、ポップアップを
操作不能にしない。
設定値は共有ストレージへ保存し、次回の対象ページ読み込み時に反映する。

### 3.4 アクセシビリティ

操作にはネイティブのフォーム要素とボタンを使用する。
キーボードフォーカスを視覚的に示し、処理結果はライブリージョンで通知する。
配色は OS のライトモードとダークモードに追従する。

## 4. 対象範囲

### 4.1 対象

- Manifest V3 のツールバーポップアップ
- 画面翻訳設定の保存とページへの反映
- ポップアップからページ内設定画面を開く導線
- Chrome と Firefox のパッケージ生成
- 関連する自動テスト

### 4.2 対象外

- GlotPress 翻訳辞書そのものの作成手順
- PolyKit の全設定項目をポップアップへ移すこと
- `translate.wordpress.org` 以外のサイトへの機能提供
- ブラウザー間で設定を同期する `chrome.storage.sync` の利用

## 5. ユーザーインターフェース

ポップアップは幅 320 px の単一画面とし、次の順序で表示する。

1. PolyKit のアイコン、製品名、説明
2. 「UI を日本語に翻訳」スイッチ
3. 「設定を開く」ボタン
4. 操作結果を示すステータス領域

### 5.1 画面翻訳スイッチ

スイッチの初期値は `chrome.storage.local` から読み込む。
値が未保存の場合は有効とする。

変更時は、先に共有ストレージへ保存する。
アクティブタブが対象サイトであれば、コンテンツスクリプトへ新しい値を送り、
ページを再読み込みして反映する。

対象サイト以外ではページを移動または再読み込みしない。
次回対象サイトを開いたときに反映されることをステータス領域で通知する。

### 5.2 設定を開くボタン

アクティブタブが対象サイトで、PolyKit のコンテンツスクリプトが動作している場合は、
同じタブでページ内設定パネルを開く。

次のいずれかに該当する場合は、
`https://translate.wordpress.org/#polykit-settings` を新しいタブで開く。

- アクティブタブが対象サイトではない
- アクティブタブを取得できない
- コンテンツスクリプトへのメッセージ送信に失敗した

操作要求を送信した後はポップアップを閉じる。

## 6. コンポーネント構成

| コンポーネント | 責務 |
| --- | --- |
| `manifest.json` | ポップアップ、権限、バックグラウンド処理を登録する |
| `popup.html` | ポップアップの意味構造と操作要素を定義する |
| `css/popup.css` | レイアウト、操作状態、ライト・ダーク配色を定義する |
| `js/popup.js` | 設定の読み書き、アクティブタブ判定、メッセージ送信を行う |
| `js/background.js` | 設定画面を現在のタブまたは新しいタブで開く |
| `js/init.js` | 共有設定をページ側へ反映し、ページ内要求を処理する |
| `js/polykit-gp-l10n.js` | 設定値に従って GlotPress UI の翻訳を実行する |

## 7. データモデル

画面翻訳設定は次の形式で保存する。

| 項目 | 値 |
| --- | --- |
| ストレージ | `chrome.storage.local` |
| キー | `polykit_translate_interface` |
| 型 | `boolean` |
| 既定値 | `true` |

ページ側の互換用ミラーは同名の `localStorage` キーを使用する。
文字列 `"false"` の場合のみ無効とし、それ以外は有効として扱う既存仕様を維持する。

## 8. メッセージ契約

メッセージ名は `polykit-` 接頭辞を付け、他の拡張機能やページスクリプトとの
衝突を避ける。

### 8.1 設定画面を開く要求

ポップアップからバックグラウンドへ次の文字列を送信する。

```text
polykit-open-settings-from-popup
```

バックグラウンドからコンテンツスクリプトへ次の文字列を送信する。

```text
polykit-open-settings
```

コンテンツスクリプトは次の処理を行う。

1. `document.documentElement.dataset.polykitOpenSettings` を `true` にする
2. `polykit:open-settings` カスタムイベントを発火する

データ属性は、ページスクリプトの初期化より先に要求を受け取った場合の保持に使う。
カスタムイベントは、初期化済みのページスクリプトへ即時に要求を伝える。

### 8.2 画面翻訳設定の更新

ポップアップからコンテンツスクリプトへ次のオブジェクトを送信する。

```json
{
  "type": "polykit-set-translate-interface",
  "enabled": true
}
```

`enabled` が真偽値でない要求は無視する。
正しい要求を受信した場合は、値をページ側 `localStorage` へ保存し、
ページを再読み込みする。

## 9. 処理フロー

### 9.1 ポップアップを開く

1. `chrome.storage.local` から共有設定を取得する
2. 保存値が真偽値ならスイッチへ反映する
3. 保存値がなければ既定値の有効状態を表示する
4. 読み込みに失敗した場合は既定値を表示し、再試行可能な状態を保つ

### 9.2 スイッチを変更する

1. 操作中のスイッチ値を取得する
2. `chrome.storage.local` へ保存する
3. アクティブタブを取得する
4. 対象サイトなら更新メッセージを送信する
5. 対象サイト以外なら次回読み込み時に反映する旨を表示する
6. メッセージ送信に失敗した場合は手動再読み込みを案内する

### 9.3 対象ページを読み込む

1. コンテンツスクリプトが共有設定を取得する
2. 真偽値の保存値があればページ側 `localStorage` へミラーする
3. PolyKit のページスクリプトと翻訳辞書を読み込む
4. ページスクリプトがミラー値に従って画面翻訳の実行可否を決定する

設定のミラーをページスクリプトの起動より先に完了させ、初回描画で古い値が
使われることを防ぐ。

## 10. 権限とセキュリティ

必要な権限は次のとおりとする。

| 権限 | 用途 |
| --- | --- |
| `storage` | ポップアップとコンテンツスクリプトで設定を共有する |
| `activeTab` | ポップアップ操作時に現在のタブを判定する |
| `*://translate.wordpress.org/*` | 対象サイトでコンテンツスクリプトを実行する |

任意 URL へのスクリプト注入は行わない。
メッセージで受け取る設定値は型を検証し、想定外の値を保存しない。
設定画面のフォールバック URL は固定値とし、外部入力から組み立てない。

## 11. エラー処理

| 状況 | 動作 |
| --- | --- |
| 共有設定が未保存 | 既定値 `true` を使用する |
| アクティブタブがない | 設定画面は新しいタブで開く |
| 対象サイト以外で設定変更 | 保存のみ行い、次回反映を通知する |
| コンテンツスクリプトが応答しない | 保存値を維持し、手動再読み込みを案内する |
| 設定画面を開くメッセージが失敗 | 固定 URL を新しいタブで開く |
| 翻訳辞書の読み込みに失敗 | PolyKit 本体を継続し、対象 UI は英語のまま表示する |

エラーはユーザーの操作を妨げない範囲でポップアップ内に表示する。
例外を未処理のまま残さない。

## 12. ブラウザー互換性

Chrome 用の `manifest.json` は Manifest V3 の
`background.service_worker` を使用する。

Firefox パッケージ生成時は `pack-ext.js` がバックグラウンド定義を
`background.scripts` に変換する。
ポップアップとメッセージ契約は両ブラウザーで共通とする。

## 13. テスト方針

### 13.1 Manifest

- `action.default_popup` が `popup.html` を指す
- ポップアップから参照するファイルが存在する
- `storage` と `activeTab` 権限が宣言されている
- Chrome 用 Manifest に `background.scripts` が混入していない
- Firefox パッケージでのみバックグラウンド定義が変換される

### 13.2 設定画面への遷移

- 対象サイトのアクティブタブでは同じタブへ要求を送る
- 対象サイト以外では固定 URL を新しいタブで開く
- メッセージ送信失敗時は固定 URL へフォールバックする
- アクティブタブがない場合も例外を発生させない

### 13.3 画面翻訳設定

- 未保存時は有効になる
- 保存値の `true` と `false` を正しく復元する
- 変更値が共有ストレージへ保存される
- 対象サイトではページ側ミラーを更新して再読み込みする
- 対象サイト以外ではページを再読み込みしない
- 真偽値以外の更新要求を無視する

### 13.4 UI 翻訳

- 設定が無効なら GlotPress UI を変更しない
- 設定が有効なら辞書にある文字列を翻訳する
- HTML 上の空白や改行の違いを許容して複合文字列を照合する
- 単語境界を維持し、別の単語の一部を誤変換しない

## 14. 受け入れ条件

次のすべてを満たした時点で実装完了とする。

- ツールバーアイコンからポップアップを開ける
- スイッチの値がポップアップを閉じても保持される
- 対象ページで設定変更すると再読み込み後の表示へ反映される
- 対象外ページで設定変更しても、そのページに副作用を与えない
- 設定ボタンが現在の状況に応じて同一タブまたは新規タブで動作する
- キーボードだけですべての操作を実行できる
- ライトモードとダークモードで文字とフォーカス表示を判別できる
- Chrome 用 ZIP と Firefox 用 XPI を生成できる
- 関連する自動テストがすべて成功する

## 15. 将来拡張時の制約

ポップアップへ設定項目を追加する場合も、共有設定の正本は
`chrome.storage.local` に統一する。
ページ固有の保存形式が必要な場合は、コンテンツスクリプトで明示的に変換し、
正本とキャッシュの優先順位を変更しない。

メッセージを追加する場合は、文字列とオブジェクトの形式、送信元、受信先、
入力検証、失敗時の動作を本書へ追記する。
権限の追加は機能に必要な最小範囲に限定し、Manifest とテストを同時に更新する。
